ESP Organizer (CHISG/Skills Tree)This document serves as the architectural and data-structure guide for the ESP Organizer, an advanced RAG platform using Contextualised Hierarchical Intelligent Semantic Grouping (CHISG). This guide details the data model, the three-stage processing pipeline, and the immediate development tasks.1. Project Overview and Key TechnologiesElementDescriptionProject NameESP Organizer (CHISG/Skills Tree)Core TechnologyContextualised Hierarchical Intelligent Semantic Grouping (CHISG)MissionTo create a dynamic, pathway-oriented knowledge base for both educational skills development (Skills Tree Rising) and complex domain analysis (e.g., Immunology).Technical StackFrontend: React/TypeScript, Backend: GoLang (API), Database: MongoDB (Raw Content), Vector Store: Weaviate (CHISG Links), LLMs: AWS Bedrock (Claude), Adobe LLM.LLM SelectionClaude 3.5 Sonnet is currently designated for Semantic Extraction and Answer Generation. Developers may use highly competent models like Claude Haiku 4.5 on Copilot for rapid prototyping, but final production logic remains with the designated Bedrock model.2. CHISG Core Architecture and Data PipelineThe CHISG system relies on a proprietary Three-Stage Semantic Processing Pipeline to create its knowledge graph, using two tiers of data: Tier 1 (Atomic Links) and Tier 2 (Narrative Threads/Recursive Links).A. CHISG Data Creation PipelineStageGoalLLM / ServiceRole and OutputInitial Content Gathering (Pre-Processing)Quickly ingest and organize source material (PDFs/Textbooks) for LLM consumption.Adobe LLM API (via PDF Spaces)Short-term Function: Answers queries directly from PDF data. Primary Function: Acts as an initial material gathering tool to generate the raw text used for the Tier 1 extraction process.1. Granular Link Extraction (Tier 1)Identify and structure every atomic relationship in the raw text.AWS Bedrock (Claude 3.5 Sonnet)Output: JSON objects following the Semantic Link (SL) schema. These are the primary vectorization inputs.2. Semantic Links (SL) - Tier 1 Atomic Knowledge UnitsVS Code Copilot Instruction: When modifying the link extraction or Go struct definitions, all new links MUST adhere to this schema to support dynamic hierarchy computation.FieldPurposeKey Constraintsource_term_generalityFor Dynamic Hierarchy: Quantifies concept breadth (0=Specific, 1=General).Use this value, NOT a fixed hierarchy_level.semantic_distanceHow far apart concepts are (0.0=Definitional, 1.0=Distant).Used in conjunction with generality for path-finding.relationship_strengthConfidence in the link's accuracy (0.0-1.0).Impacts RAG result filtering.relation_typeThe nature of the link (e.g., causes, treats, component_of).Must be a typed relationship for graph traversal.is_parent_of, is_child_ofGraph connectivity arrays (currently empty).IMMEDIATE NEXT STEP: Must be populated during initial extraction/post-processing.2. Tier 2 Recursive Processing PipelineVS Code Copilot Instruction: The RAG query service must implement this 7-step pipeline to leverage the full CHISG context, including the Derived Semantic Links that capture distant knowledge.The core of the system is the Recursive Pipeline (steps 4-6) where the LLM uses the narrative summary of the initial thread to extract new, higher-level links.Query ReceptionInitial SL Search (Tier 1)HSG Thread Construction (Partial)Summary Generation (LLM uses partial thread to generate narrative text)Derived Link Extraction (LLM extracts new SLs from the summary text)Final HSG Construction (Complete HSG with original + derived links)Answer Generation (Claude 3.5 uses the complete, structured context)3.
